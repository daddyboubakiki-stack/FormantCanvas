# Gamification Protocol — Core Layer v0.1

ゲーミフィケーションは必須機能ではなく、学習、探索、練習、継続、作業を助ける場合だけ使う設計手段です。

## 1. 先に目的を確認する

- 誰が、何のために、どの場面で使うか。
- ゲーム要素が理解、練習、探索、継続のどれを助けるか。
- ゲーム要素なしでも主要機能が成立するか。
- 集中、効率、信頼性、落ち着きを損なわないか。

明確な利益がなければ、入れない判断を正解とします。教育アプリであることだけをゲーム化の理由にしません。

## 2. 強度を用途へ合わせる

| Level | 内容 | 適する例 |
|---|---|---|
| 0 — None | ゲーム要素なし | 高リスク操作、研究・業務・専門分析 |
| 1 — Subtle | 進捗、即時フィードバック、静かな達成表示 | 大人向け学習、専門・生産性ツール |
| 2 — Playful | 探索、図鑑、意味のある収集、小さな挑戦 | 子ども・初学者向け教材、創作体験 |
| 3 — Game-forward | 物語、ステージ、明示的ゲームループ | ゲーム、学習ゲーム、遊び中心の体験 |

研究・専門ツールではLevel 0〜1が適する場合が多く、子ども・初心者向けではLevel 2を検討できます。年齢だけで自動決定しません。

## 3. 探索・成長・自律性を優先する

優先候補：探索、発見、選択、習熟、自己ペースの挑戦、意味のあるコレクション、即時フィードバック、振り返り、小さな達成。

慎重に扱うもの：公開ランキング、連続記録の喪失、競争タイマー、学習と無関係なポイント、ランダム報酬、FOMO、過度な通知、失敗を恥じさせる演出。

採用する場合は、目的上の利益、非競争的な代替、退出・無効化方法、対象者への悪影響を確認します。

## 4. 内容と報酬を結びつける

コレクションや進捗は、発見した知識、試した条件、完成した作品、習得した技能等へ結びつけます。無関係なデジタル物品を集めることだけで利用を引っ張りません。

## 5. 注意とデータを搾取しない

- 滞在時間や起動回数だけを成功指標にしない。
- streakやランキングのためだけに余計な個人データを取得しない。
- 色、音、動きだけで進捗や勝敗を伝えない。
- 演出の軽減・OFF、競争表示の非表示等を必要に応じて用意する。
- 早く目的を達成して終了できることも良いUXと認める。

## 6. 調整・撤去可能にする

ゲーム要素を主要ロジックへ密結合させず、強度を下げる、別方式へ置き換える、外すことを可能にします。実装後に、目的達成、動機づけ、焦り、比較ストレス、疲労、幼く見えすぎないかを確認します。

原則：**Gamification is optional, adjustable, reversible, and subordinate to purpose.**
