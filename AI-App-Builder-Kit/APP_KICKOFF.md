# App Kickoff / 企画カルテ v0.1

実装より先に「誰のために、何のために、どんな状況で、何を守って作るか」の共通認識を作るための手順です。企画カルテは固定契約ではなく、現在の仮説です。試作、調査、利用者テストから学んだら更新します。

## K0 — AIの基本動作

1. 会話、既存Brief、添付資料から分かる項目を先に埋める。
2. 回答済みの質問を繰り返さない。
3. 不明で、設計への影響が大きい項目だけ質問する。
4. 原則として一度に1〜3問、Mini全体でも5〜8問程度にまとめる。
5. 「未定」「AIに提案してもらう」を認める。
6. AIが置く値は`仮説`と明記する。
7. Briefを提示し、認識のずれを確認してから本格実装へ進む。

## K1 — Mini Kickoff

小さな企画や初期アイデアの標準です。次の項目を、既知情報でまとめてから不足分だけ尋ねます。

### 対象と目的

- **Target**：自分専用 / 子ども / 中高生 / 大学生 / 一般 / 専門家 / チーム / 複数
- **Age**：年齢帯または限定なし
- **Experience level**：完全初心者 / 初級 / 中級 / 上級・専門 / 混在
- **Purpose**：学ぶ / 練習 / 分析 / 制作 / 遊ぶ / 記録・管理 / 効率化 / 共有・協力 / 複数
- **Core action**：利用者が繰り返す中心行動

### 利用状況

- **Context of use**：家庭 / 学校 / 大学・研究 / 職場 / 移動中 / 複数
- **Devices**：スマートフォン / タブレット / PC / 複数
- **Session length**：1分未満 / 1〜5分 / 5〜20分 / 20分以上 / 可変
- **Frequency**：一度だけ / ときどき / 毎週 / 毎日 / 集中的な期間

### 体験と範囲

- **Experience / Art direction**：望む印象を複数選択。美的方向をAIが勝手に決めない。
- **Gamification**：Level 0 / 1 / 2 / 3 / AIに提案してもらう
- **Network**：オフライン必須 / オンライン可 / 常時オンライン / 未定
- **Storage / Login**：保存なし / 端末保存 / クラウド保存、ログインなし / 任意 / 必須 / 未定
- **Visibility**：自分だけ / 限定共有 / 組織内 / 一般公開 / 未定
- **Maturity goal**：アイデア検証 / 動く試作 / 限定利用 / 公開可能 / 運用可能
- **Priorities**：最優先を1〜3個
- **Must-have / Must-not**：絶対必要なもの、絶対避けるもの

複数選択が自然な項目は複数選択を許可します。チャットでは、既知情報を含む仮入力表を示し、未確定の項目だけ選択肢で尋ねます。

## K2 — AIが先に埋める例

```md
現時点の理解：
- Target: 大学生・初学者
- Purpose: 専門用語を短時間で復習する
- Devices: スマートフォン中心
- Session length: 1〜5分（仮説）

設計に影響する未確定項目は次の3点です。
1. 保存：なし / 端末内 / ログイン同期 / AIに提案してもらう
2. 公開範囲：自分だけ / 仲間と共有 / 一般公開
3. ゲーム性：Level 0 / 1 / 2 / AIに提案してもらう
```

## K3 — Deep Kickoffへ進む条件

次のいずれかがある場合、Miniの後に関係する項目だけ深掘りします。

### 教育・子ども

学習目標、学年・既習事項、授業か自主学習か、大人の関与、評価、教材の根拠、文字理解、外部リンク、課金、共有、個人情報、誤操作時の安全。

### 研究・専門データ

必要精度、出典、証拠区分、不確実性、再現性、出力形式、監査、変更承認、表示密度、処理速度。

### AI機能

AIの役割、決めてよい範囲、人間の最終判断、送信データ、誤答時の扱い、停止・非対応時の代替、費用。

### 複数ユーザー・公開

役割と権限、招待、公開範囲、モデレーション、通報、削除、所有権、監査ログ。

### 保存・アカウント・課金

保存対象、保存先、保持期間、削除・エクスポート、同期競合、認証、復旧、料金表示、解約。

### 高リスク領域

健康、法律、金融、安全、評価・採用等で、誤りの影響、人間の確認、免責だけに頼らない安全策、専門家レビューを検討します。

### 音声・カメラ・位置・センサー

権限の理由、端末内処理、保存・送信、無許可時の代替、周囲への配慮、ミュート、削除。

## K4 — Brief生成

Mini回答を[`PROJECT_BRIEF_TEMPLATE.md`](PROJECT_BRIEF_TEMPLATE.md)へまとめます。未回答は`未定`、AI提案は`仮説`と明記します。特に次を明確にします。

- 目的と成功条件
- 中心行動と最初の試作
- 保護対象
- 変更可能な範囲
- Must-have / Must-not
- 高リスクの仮定
- 次に検証すること

## K5 — 共通認識チェック

AIはBrief提示後、次のように一度だけ確認します。

> このBriefは、想像しているプロダクトと概ね同じですか？ 大きな違いがなければ、最小試作の範囲を提案します。

細部の未定をすべて確定させる必要はありません。大きなずれがなければ、小さく試して更新します。

## K6 — 生きた文書として扱う

Briefを守るためにアプリを作るのではありません。より良いアプリを作るためにBriefを更新します。対象、端末、ゲーム性、機能、優先順位が変わったときは、理由と影響を記録します。
